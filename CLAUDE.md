# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Personal portfolio of Robin Regis, freelance full-stack developer: featured projects with case studies, services,
work experience, about and contact. Built with Next.js 16 (App Router), React 19, TypeScript and Tailwind CSS 4.
All content comes from Sanity (Studio in `studio-perso/`). The site targets freelance clients and is in French.

## Development Commands

```bash
npm run dev          # Next.js dev server (Turbopack)
npm run build        # Production build
npm run lint         # ESLint flat config (eslint-config-next)
npm run typecheck    # tsc --noEmit
npm run typegen      # Regenerate sanity/types.ts (runs `sanity schema extract` + `sanity typegen generate` in studio-perso)
npm run knip         # Unused files / dependencies

cd studio-perso && npm run dev      # Sanity Studio on :3333
cd studio-perso && npm run deploy   # Deploy the hosted Studio
```

## Architecture

```
app/                    # App Router
  layout.tsx            # Fonts, metadata, header/footer (profile fetched once, cached)
  page.tsx              # Home: one HOME_QUERY, sections in components/home/
  realisations/[slug]/  # Case study page + its Open Graph image
  mentions-legales/     # Legal notice (legalNotice singleton + profile email; the phone is never shown)
  api/contact/          # Contact form: validation, honeypot, reCAPTCHA v3 check, sends with Resend
  api/revalidate/       # Signed Sanity webhook → revalidateTag(<document type>)
  sitemap.ts, manifest.ts, opengraph-image.tsx, not-found.tsx
components/
  ui/                   # Design system primitives (Button/ButtonLink, Tag, SectionHeading, Sticker, BrowserFrame, Container)
  layout/               # Header (client: mobile menu), Footer, Logo
  home/                 # Home sections (Hero, ClientsMarquee, Projects, Services, Experience, About, Testimonials, Contact)
  projects/             # ProjectCard (stretched link to case study or live site)
  contact/              # ContactForm (client: react-hook-form) + send-message (POST /api/contact, EmailJS fallback)
  rich-text.tsx         # Portable Text renderer
  sanity-image.tsx      # next/image wrapper (hotspot → object-position, LQIP)
sanity/
  client.ts             # @sanity/client + sanityFetch (Next.js cache: revalidate 1h + tags per document type)
  queries.ts            # GROQ queries wrapped in defineQuery (TypeGen source)
  types.ts              # GENERATED by `npm run typegen` — never edit by hand
  image.ts, image-loader.ts  # URL builder and next/image loader (Sanity CDN resizes images)
  labels.ts             # French labels for Studio option lists
lib/                    # cx, site constants (SITE_URL, NAV_ITEMS, formatPeriod), SEO helpers, OG image renderer,
                        # contact rules shared by form and API (contact.ts), reCAPTCHA loader (recaptcha.ts)
studio-perso/           # Standalone Sanity Studio (v6): schemaTypes/, structure.ts (profile + legalNotice singletons)
brand/                  # Logos (square badge, horizontal lockup): SVG with outlined text + PNG exports
```

### Data flow

- Server Components fetch Sanity with `sanityFetch({query, params, tags})`; results are cached by Next.js and
  revalidated hourly or on demand by the webhook (tag = document `_type`).
- When a query changes, run `npm run typegen` and use the generated `*_QUERY_RESULT` types.
- The profile is a singleton document with the fixed `_id` `"profile"`; query it with `_type == "profile" && _id == "profile"`.
  Same pattern for the legal notice (`_id` `"legalNotice"`).
- `sanityFetch` applies French typography to every string it returns (non-breaking space before `: ; ! ?`).
- Images: always render Sanity images with `<SanityImage>` and query them with the `imageFields` fragment.

### Content model (studio-perso/schemaTypes)

`profile` (singleton, incl. the `process` steps shown under the services), `legalNotice` (singleton), `project`,
`jobExperience`, `service` (with `deliverables` and `stack`), `educationalBackground`, `clientReview`, plus objects
`richText`, `stat`, `skillGroup`, `socialLink`, `link`, `processStep`. `information` and `portfolioFilter` are legacy
types kept only for the old site. Never delete a field that holds data: mark it `deprecated` + `readOnly` + hidden when
empty (see the legacy fields in `project`, `jobExperience`, `service`). Option lists shown on the site have French labels in
`sanity/labels.ts`: keep both in sync.

## Design System

Editorial neo-brutalism (bold but readable, deliberately distinct from the Fromton app):
- Tokens in `app/globals.css` (`@theme`): `paper` background, `ink` text/borders, `mint` brand accent, `lilac` and
  `coral` strong accents, card pastels (`sun`, `rose`, `sky`, `lime`), hard shadows
  `shadow-brutal-sm|brutal|brutal-md|brutal-lg|brutal-xl` (on dark bands: `shadow-[8px_8px_0_0_var(--color-paper)]`).
- `bg-grid` utility: graph-paper background whose lines follow `currentColor` (works on light and dark sections).
- Sections are numbered (`SectionHeading index="01"`); `Sticker` for tilted labels, `BrowserFrame` around screenshots.
- 2px `border-ink` borders, `rounded-2xl`/`rounded-3xl` cards, pill buttons; interactive cards lift on hover
  (`hover:-translate-1 hover:shadow-brutal-lg`).
- Titles use the `font-heading` utility (Archivo expanded, 800). Labels/eyebrows/tags use `font-mono`.
- Animations (marquees, rotating badge) stay subtle and stop with `prefers-reduced-motion`.

## Conventions

- All user-facing text is in French; content text belongs in Sanity, not in components.
- Prefer Server Components; add `'use client'` only for interactivity (header menu, contact form).
- Accessibility: one `h1` per page, labelled sections, visible focus, `sr-only` text for icon-only links.
- Code style: Prettier (`semi: false`, `singleQuote`, `printWidth: 100`, Tailwind class sorting).
